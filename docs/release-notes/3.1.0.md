# CodeForge Mobile 3.1.0

Android-Entwicklungsumgebung auf dem Handy: Editor, Terminal, Git, Gradle-Build, Language Server, Layout-Designer und Asset Studio – alles in einer App.

> ⚠️ **Vorabversion / Debug-APK.** Das Release ist mit dem Android-Debug-Schlüssel signiert und noch nicht systematisch auf Geräten getestet (Checkliste: `docs/device-test-checklist.md`). Bitte Fehler als Issue melden.

## Änderungen seit 3.0.9

### Neu

- **Plugin-API 3: Tests je Datei:** Test-Quellen für Plugins (`PluginLanguagePoints.TEST_PROVIDER`, Berechtigung `run`): Start-Knopf an jeder Testzeile (nach dem Lauf grün oder rot), „Tests dieser Datei ausführen“ in der Befehlspalette; das Ausgabeblatt listet alle Tests, fehlgeschlagene zuerst.
- **Plugin-API 3: Navigation und Umbenennen ohne Sprachserver:** Neue Andockstellen `DEFINITION_PROVIDER`, `REFERENCE_PROVIDER` und `RENAME_PROVIDER`: Plugins beantworten „Gehe zur Definition“, „Verwendungen suchen“ und „Umbenennen“, wenn kein Sprachserver ein Ergebnis liefert.
- **Plugin-API 3: Fortschritt, Rückfragen, Benachrichtigungen:** `context.feedback()`: `withProgress` (Leiste über allen Bildschirmen), `confirm` und `choose` (Dialoge, das Plugin wartet auf die Antwort) sowie `notify` (Systembenachrichtigung, neue Berechtigung `notifications`).
- **Plugin-API 3: Fortschritt, Rückfragen, Benachrichtigungen:** Beim Deaktivieren eines Plugins enden seine offenen Rückfragen und Fortschrittsanzeigen automatisch.

### Geändert

- **Sprachserver: weniger Anfragen:** Gleiche LSP-Anfragen, die gleichzeitig laufen, teilen sich eine Antwort.

### Fixes

- Release-Build schlug fehl („InternalProblems … removed in Gradle 9.6.0“): Der Gradle-Wrapper war auf 9.9.1 gehoben worden, AGP 8.13 läuft aber nur bis Gradle 9.5.

## Installation

1. APK `app-debug.apk` herunterladen und Prüfsumme mit `SHA256SUMS.txt` vergleichen.
2. Installieren (Installation aus unbekannten Quellen erlauben).
3. Beim ersten Start dem Onboarding folgen: Berechtigungen erteilen, Bootstrap installieren, Setup mit `codeforge-env` ausführen.

Unterstützte Architekturen: **aarch64** (Hauptziel) und **arm**.

## Bekannte Einschränkungen

- **Code Folding** fehlt (Sora-Editor 0.23.4 kann eingeklappte Bereiche nicht darstellen).
- `targetSdk = 28` ist nötig, damit Termux-Binaries ausführbar sind – **kein Play-Store-Release möglich**; Verteilung über GitHub/F-Droid/Sideload.
- Das Android-SDK 37 (`android-sdk-37.0.0`) steht nur für aarch64 zur Verfügung.
- Gerätetests (Bootstrap, W^X, Layouts, LSP) sind noch offen.
