# CodeForge Mobile 3.3.0

Android-Entwicklungsumgebung auf dem Handy: Editor, Terminal, Git, Gradle-Build, Language Server, Layout-Designer und Asset Studio – alles in einer App.

> ⚠️ **Vorabversion / Debug-APK.** Das Release ist mit dem Android-Debug-Schlüssel signiert und noch nicht systematisch auf Geräten getestet (Checkliste: `docs/device-test-checklist.md`). Bitte Fehler als Issue melden.

## Änderungen seit 3.2.0

### Neu

- Store: Einreichungen werden automatisch geprüft (Workflow `submission.yml`, `check_submission.py`: Archiv, Manifest, Store-Regeln, Version bei Updates) und mit Bericht samt SHA-256 kommentiert. / Automatic checks for store submissions.
- CI prüft, ob das Plugin-SDK der Code-Vorlagen zu `:libs:plugin-api` passt (`build_plugin_sdk.py --check`). / CI checks that the code templates' plugin SDK is current.
- Terminal-Einstellungen → „Berechtigungen & Integration“: erklärt, warum das eingebaute Terminal keine Termux-Berechtigung „Befehle ausführen“ und kein `allow-external-apps` braucht, zeigt den Status von „Über anderen Apps einblenden“ und der Akku-Optimierung …
- Terminal-Einstellungen → „termux.properties“: ganze Datei im Vollbild-Editor bearbeiten; vor dem Speichern wird die bisherige Datei nach `~/.termux/backup/termux.properties.<Zeit>.bak` gesichert (die letzten 10 bleiben), danach werden die Einstellungen neu …
- Projektvorlagen für Plugin-Autoren (13, auch im Store): je Plugin-Art ein eigenständiges Projekt – Farbschema, Icon-Theme, Sprachpaket, Grammatik, Snippets, Sprachserver, Formatierer, Werkzeug, Bundle, Projektvorlage, Agent-Werkzeug, Code (Sandbox) und Code …
- Vorlagen-Engine: `{{{name}}}` lässt einen Platzhalter stehen, Endung `.tpl` wird beim Erzeugen entfernt. / Template engine: escaped placeholders and `.tpl` suffix.
- Tree-sitter-Highlighting aktiv (Einstellung „Tree-sitter verwenden“) für Kotlin, Java, JSON, XML, C, C++, Bash, CMake, TOML, YAML: Farben kommen aus dem aktiven Editor-Theme (auch Theme-Plugins), zusätzliche Abfrage-Prädikate `#eq?`, `#any-of?`, …
- Theme-Builder neu als Projekt-Werkzeug (Seitenleiste → Theme), nach dem Vorbild von materialkolor.com: Material-3-Theme aus einer Grundfarbe oder einem Bild, 9 Palettenstile, 3 Kontraststufen, eigene Sekundär-/Tertiär-/Neutral-/Fehler- Paletten, Live-Vorschau …
- `:libs:color-utilities` (Googles material-color-utilities, Kotlin, Apache 2.0) und `:libs:theme-kit` (Engine, Code-Erzeugung, Projekt-Übernahme, Plugin-Export). / Google's color utilities and a theme kit module.
- Plugin-Sandbox (`libs/plugin-sandbox`): Code-Plugins mit `"sandbox": true` laufen im isolierten Prozess `:plugin_sandbox` (eigene UID, ohne Rechte), Messenger-IPC, `InMemoryDexClassLoader`; Editor-Aktionen, Quick-Fixes, Vervollständigung, Hover, Definition, …
- Code-Plugin „Textwerkzeuge“ (`text-tools`, Sandbox): 17 Textaktionen. / Code plugin “Text tools” (sandboxed).

### Geändert

- Vorlage „Keine Activity“ (1.0.1) legt den Quellordner des Packages wieder an; Code-Vorlagen erklären, dass `ANDROID_HOME` im Terminal gesetzt ist und die Build-Tools aus dem SDK-Manager kommen. / Small template fixes.
- Editor-Einstellungen → Editor-Theme: Neben „Automatisch“, Dark+ und Light+ sind jetzt die Editor-Themes aller installierten Theme-Plugins (Store) wählbar, unabhängig vom App-Farbschema; wird das Plugin entfernt, gilt wieder „Automatisch“.
- Projektvorlagen: Die 9 mitgelieferten Android-Vorlagen (Keine/Leere Activity, Native C++, Basic, Navigation Drawer, Bottom Navigation, Tabs, Ohne AndroidX, Jetpack Compose) sind jetzt normale Vorlagen-Plugins (`com.codeforge.plugin.android-*.template`), …
- Plugin-API 1 für Code-Plugins abgekündigt (erlaubt `shell`/`lsp` ohne Berechtigung): Warnung in der Plugin-Liste und nach der Installation, ab CodeForge 3.4.0 abgelehnt. / Plugin API 1 for code plugins is deprecated (rejected from 3.4.0).
- Eigene CodeForge-Farbgebung (Indigo `#6366F1` aus dem Icon, Cyan `#06B6D4` als Akzent) statt Material-Standard-Lila. / CodeForge's own color scheme from the app icon.
- Einstellungen → Erscheinungsbild ersetzt den bisherigen Theme-Bildschirm: Hell/Dunkel/System, dynamische Farben, CodeForge oder Farbschemata aus dem Store, Icon- und Sprachpakete. / New appearance settings page.
- Store-Farbschemata werden aus ihren Grundfarben vollständig abgeleitet (Container, Flächen, Ränder) und folgen dem Hell/Dunkel-Modus, wenn das Paket beide Varianten hat. / Store color schemes derive a full scheme and follow light/dark mode.

### Fixes

- Sandbox-Plugins luden nicht (Zeitüberschreitung): `Application.onCreate` lief auch im isolierten Prozess `:plugin_sandbox` und brachte ihn zum Absturz (Hilt, DataStore, Termux, Dienste).
- REST-Client: Regex mit unescapter `}` warf auf Android `PatternSyntaxException`. / REST client regex crash on Android (unescaped `}`).

### Entfernt

- Die 15 eingebauten Farb-Presets und die eigene Palette in der App; die Presets gibt es weiter im Store, eine frühere Auswahl wird beim Installieren des Pakets übernommen. / Built-in presets and custom palette (presets remain in the store).
- Altlasten des früheren Erweiterungs-Managers: toter Plugins-Vollbildschirm (`PluginsRoute`), 97 ungenutzte Texte (DE/EN). / Leftovers of the former extensions manager: dead plugins screen and 97 unused strings.
- `code-plugins/code-plugin.gradle.kts` und `examples/plugin-packaging.gradle.kts` → ein gemeinsames `gradle/code-plugin.gradle.kts` für alle Code-Plugins (Android-Library und Kotlin, Build-Info, Signatur); Vorlage und Leitfaden-Beispiel auf API 4. / One shared …

## Installation

1. APK `app-debug.apk` herunterladen und Prüfsumme mit `SHA256SUMS.txt` vergleichen.
2. Installieren (Installation aus unbekannten Quellen erlauben).
3. Beim ersten Start dem Onboarding folgen: Berechtigungen erteilen, Bootstrap installieren, Setup mit `codeforge-env` ausführen.

Unterstützte Architekturen: **aarch64** (Hauptziel) und **arm**.

## Bekannte Einschränkungen

- **Code Folding** fehlt (Sora-Editor 0.23.4 kann eingeklappte Bereiche nicht darstellen).
- `targetSdk = 28` ist nötig, damit Termux-Binaries ausführbar sind – **kein Play-Store-Release möglich**; Verteilung über GitHub/F-Droid/Sideload.
- Das Android-SDK 37 (`android-sdk-37.0.0`) steht nur für aarch64 zur Verfügung.
- Gerätetests (Bootstrap, W^X, Layouts, LSP) sind noch offen.
