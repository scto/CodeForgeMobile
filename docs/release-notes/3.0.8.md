# CodeForge Mobile 3.0.8

Android-Entwicklungsumgebung auf dem Handy: Editor, Terminal, Git, Gradle-Build, Language Server, Layout-Designer und Asset Studio – alles in einer App.

> ⚠️ **Vorabversion / Debug-APK.** Das Release ist mit dem Android-Debug-Schlüssel signiert und noch nicht systematisch auf Geräten getestet (Checkliste: `docs/device-test-checklist.md`). Bitte Fehler als Issue melden.

## Änderungen seit 3.0.7

### Neu

- Befehlspalette im Editor (⌘-Symbol, `Strg+Umschalt+P`): eingebaute Aktionen je nach Server-Fähigkeiten und Dateityp, die vom Sprachserver gemeldeten Befehle (`executeCommandProvider.commands`, ohne interne wie `*.apply*`/`_…`) und Plugin-Befehle.
- Refactoring-Menü (Werkzeug-Symbol, `Strg+Umschalt+R`): Code-Actions `refactor.*`/`source.*` für Cursor bzw. Auswahl (`context.only`), sortiert nach Art, dazu „String-Ressource extrahieren“.
- Palette: „Imports organisieren (Sprachserver)“ (`source.organizeImports`) und „Alle behebbaren Probleme beheben“ (`source.fixAll`); liefert der Server genau eine Aktion, wird sie direkt angewendet.
- Umbenennen im Dateibaum passt Verweise an: zuerst `workspace/willRenameFiles` der Sprachserver; liefern sie nichts, ändert CodeForge bei Ordnern in `src/*/java|kotlin` selbst `package`- und `import`-Zeilen (auch `import static`) sowie voll qualifizierte …
- `scripts/check_android_regex.py`: findet Regex-Literale, die auf Android abstürzen; läuft im Workflow „Build Debug APK“.

### Geändert

- LSP-Client liest `codeActionKinds`, `executeCommandProvider.commands` und `workspace.fileOperations` und meldet selbst `workspace.fileOperations`/`executeCommand`.

### Fixes

- Absturz `PatternSyntaxException` beim Öffnen von „String-Ressource extrahieren“: Der Regex `\$\{[^}]*}` enthielt ein unescaptes `}` – die JVM akzeptiert das (Tests grün), Androids ICU-Regex nicht.
- Gleicher Fehler in `GradleBuildParser` (Abhängigkeits-Updates bei Versionen wie `${kotlinVersion}`).
- CHANGELOG: doppelter, aus Commits erzeugter Abschnitt `[3.0.7]` entfernt.

## Installation

1. APK `app-debug.apk` herunterladen und Prüfsumme mit `SHA256SUMS.txt` vergleichen.
2. Installieren (Installation aus unbekannten Quellen erlauben).
3. Beim ersten Start dem Onboarding folgen: Berechtigungen erteilen, Bootstrap installieren, Setup mit `codeforge-env` ausführen.

Unterstützte Architekturen: **aarch64** (Hauptziel) und **arm**.

## Bekannte Einschränkungen

- **Code Folding** fehlt (Sora-Editor 0.23.4 kann eingeklappte Bereiche nicht darstellen).
- `targetSdk = 28` ist nötig, damit Termux-Binaries ausführbar sind – **kein Play-Store-Release möglich**; Verteilung über GitHub/F-Droid/Sideload.
- Das Android-SDK 37 (`android-sdk-37.0.0`) steht nur für aarch64 zur Verfügung.
- Gerätetests (Bootstrap, W^X, Layouts, LSP) sind noch offen.
