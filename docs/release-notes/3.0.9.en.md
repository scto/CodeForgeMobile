# CodeForge Mobile 3.0.9

Android development environment on your phone: editor, terminal, Git, Gradle build, language servers, layout designer and Asset Studio – all in one app.

> ⚠️ **Pre-release / debug APK.** Signed with the Android debug key and not yet systematically tested on devices (checklist: `docs/device-test-checklist.md`). Please report bugs as issues.

## Changes since 3.0.8

### New

- **Plugin-API 3, Teil 5: Sprache, Ausführen, Oberfläche:** Vervollständigungs- und Hover-Quellen für Plugins (`PluginLanguagePoints.COMPLETION_PROVIDER`/`HOVER_PROVIDER`): Vorschläge werden mit denen des Sprachservers zusammengeführt, Hover greift, wenn der Server nichts liefert.
- **Plugin-API 3, Teil 5: Sprache, Ausführen, Oberfläche:** Ausführen-/Test-Aufgaben (`RUN_TASK`, Berechtigung `run`) in der Befehlspalette; Ausgabe, Exit-Code und Testzusammenfassung live in einem Blatt, abbrechbar.
- **Plugin-API 3, Teil 5: Sprache, Ausführen, Oberfläche:** Neues Modul `:libs:plugin-ui-api`: Plugins liefern eigene Compose-Bereiche (`PluginPanel`, Berechtigung `ui`), die über die Befehlspalette geöffnet werden und Dateien öffnen oder Meldungen zeigen können.
- **Einstellungsseiten für Plugins:** `contributes.settings` im Manifest: Einstellungen vom Typ Text, Ja/Nein, Auswahl und Zahl (mit Bereich); Seite im Plugins-Bildschirm unter „Einstellungen“, sofort gespeichert, „Vorgabe wiederherstellen“ je Eintrag.
- **Einstellungsseiten für Plugins:** `${setting:key}` in `lspServers`, `formatters` und `tools` – auch rein deklarative Plugins sind damit einstellbar.
- **Einstellungsseiten für Plugins:** Plugin-API 3: `context.settings()` mit `getString`/`getBoolean`/`getInt` und `addChangeListener`.
- **Sprachserver: Robustheit, mehrere Server:** Zeitlimit für jede LSP-Anfrage (je Methode, z. B. 10 s Vervollständigung, 60 s Umbenennen, 180 s Start) mit `$/cancelRequest`; auch ein abgebrochener Aufrufer bricht die Anfrage beim Server ab.
- **Sprachserver: Robustheit, mehrere Server:** Automatischer Neustart abgestürzter Server (Hinweis im Editor); nach mehr als 3 Abstürzen in 3 Minuten nicht mehr.
- **Sprachserver: Robustheit, mehrere Server:** Mehrere Server je Sprache: Einstellung „Zusätzlich starten“ je Server (z. B. kmp-lsp neben dem Kotlin Language Server).
- **Sprachserver: Robustheit, mehrere Server:** `lspServers[].rootMarkers`: Arbeitsordner je Datei (nächster Ordner mit z. B. `pyproject.toml`), eigene Sitzung je Ordner.
- **Plugin-API 3, Teil 2: Editor:** Editor-Aktionen für Plugins (`PluginExtensionPoints.EDITOR_ACTION`, Berechtigung `editor`): Zugriff auf Text, Cursor und Auswahl der aktiven Datei (`EditorContext`), Änderungen als Effekte (`ApplyEdits`, `MoveCaret`, `Select`, `CreateFile`, `OpenFile`, …
- **Plugin-API 3, Teil 2: Editor:** Schnellkorrektur-Quellen (`QUICK_FIX_PROVIDER`): Vorschläge zu den Diagnosen am Cursor.
- **Plugin-API 3, Teil 2: Editor:** Eingebaute Aktionen über dieselbe Andockstelle: „Zeilen sortieren“, „Doppelte Zeilen entfernen“, „Groß-/Kleinschreibung umschalten“.
- **Plugin-API 3, Teil 2: Editor:** Neue Plugin-Ereignisse: `EditorActivated`, `DiagnosticsChanged`, `BuildStarted`, `BuildFinished`, `ProjectOpened`, `ProjectClosed`; neue Berechtigungen `editor`, `build-events`, `project-events`.
- **Plugin-API 3, Teil 1:** Gemeinsames `ExtensionRegistry` (`core:domain`): typisierte `ExtensionPoint<T>`, jeder Beitrag gehört einem Plugin (oder der App), einzeln per `Disposable` oder gesammelt per `unregisterAll` abmeldbar, beobachtbar als `StateFlow`.
- **Plugin-API 3, Teil 1:** Plugin-API 3: `context.logger(tag)` (Protokoll je Plugin, im Plugins-Bildschirm unter „Protokoll“, zusätzlich im App-Log als `plugin/<id>/<tag>`) und `context.register(point, value)` mit Berechtigungsprüfung je Andockstelle.
- **Plugin-API 3, Teil 1:** `dependsOn`: Laden in Abhängigkeitsreihenfolge; Deaktivieren/Entfernen entlädt Abhängige zuerst, Einschalten lädt wartende nach.

## Installation

1. Download the APK `app-debug.apk` and compare its checksum with `SHA256SUMS.txt`.
2. Install it (allow installation from unknown sources).
3. On first launch follow the onboarding: grant permissions, install the bootstrap, run the setup with `codeforge-env`.

Supported architectures: **aarch64** (main target) and **arm**.

## Known limitations

- **Code folding** is missing (Sora Editor 0.23.4 cannot render folded regions).
- `targetSdk = 28` is required so that Termux binaries can run – **no Play Store release possible**; distribution via GitHub/F-Droid/sideload.
- Android SDK 37 (`android-sdk-37.0.0`) is only available for aarch64.
- Device tests (bootstrap, W^X, layouts, LSP) are still open.
