# CodeForge Mobile 3.0.6

Android-Entwicklungsumgebung auf dem Handy: Editor, Terminal, Git, Gradle-Build, Language Server, Layout-Designer und Asset Studio – alles in einer App.

> ⚠️ **Vorabversion / Debug-APK.** Das Release ist mit dem Android-Debug-Schlüssel signiert und noch nicht systematisch auf Geräten getestet (Checkliste: `docs/device-test-checklist.md`). Bitte Fehler als Issue melden.

### Fixes

- **Klonen: Zielordner:** Der Klon-Bildschirm las den Standard-Zielordner nur einmal beim Erzeugen des ViewModels.
- Kotlin-Sprachserver: Die Java-Voraussetzung gilt nur als erfüllt, wenn unter `lib/jvm` ein JDK 17–21 liegt (der eingebettete Compiler kann Java 22+ nicht lesen); mit nur JDK 25 wird `openjdk-17` nachinstalliert, `findJavaHome` wählt dann die passende Version.
- „Formatierer verwalten“: ausgeschaltete Plugin-Formatierer behalten ihren Namen.
- `ToolPluginsValidTest` kennt das README-Werkzeug (29 Plugins, 9 Werkzeuge).
- JAVA_HOME: bevorzugt JDK 21 (Ziel des Terminal-Setups) statt des höchsten installierten JDK.
- Startseite: Projekte im Projektstamm lassen sich wieder entfernen – neu „Projekt löschen“ mit Bestätigungsdialog (löscht den Ordner, nur innerhalb des Projektstamms); „Aus Liste entfernen“ bleibt für Projekte außerhalb.
- „Projekt schließen“/Zurück: Die Startseite wird nicht mehr zusätzlich über das Projekt gelegt; Zurück führt nicht mehr ins Projekt zurück.
- Compose-Vorlage: Unit-Tests werden für alle Varianten aktiviert, damit die Compose-Vorschau-Aufgaben auch für release angelegt werden können (`:tasks` brach ab).

## Installation

1. APK `app-debug.apk` herunterladen und Prüfsumme mit `SHA256SUMS.txt` vergleichen.
2. Installieren (Installation aus unbekannten Quellen erlauben).
3. Beim ersten Start dem Onboarding folgen: Berechtigungen erteilen, Bootstrap installieren, Setup mit `codeforge-env` ausführen.

Unterstützte Architekturen: **aarch64** (Hauptziel) und **arm**.

## Bekannte Einschränkungen

- **Code Folding** fehlt (Sora-Editor 0.23.4 kann eingeklappte Bereiche nicht darstellen).
- `targetSdk = 28` ist nötig, damit Termux-Binaries ausführbar sind – **kein Play-Store-Release möglich**; Verteilung über GitHub/F-Droid/Sideload.
- Das Android-SDK 37 (`android-sdk-37.0.0`) steht nur für aarch64 zur Verfügung.
- Gerätetests (Bootstrap, W^X, Layouts, LSP) sind noch offen.
